# RL P0：連通性特徵（未訪區域的連通分量數）

> 對應 `handover-rl-solver.md` §6.5 的 **P0**。分支 `feat/rl-a2-training`、worktree `zip-rl`。
> 日期：2026-09-05（Asia/Taipei）
> **§1–§5 在看到 A/B 結果之前就寫定**（判讀規則事前登記，避免事後搬門檻）。

---

## 1. 一句話

在 `PuzzleEnvV2` 的純量觀測加上**未訪區域的連通分量數**，用 3 seed × 2 臂在 4×4 對照，
檢驗「補上死路的提前訊號」能不能買到大於 seed 雜訊（±0.04）的提升。

## 2. 機制：為什麼是連通分量

**白話**：一筆畫不能瞬移。你走的某一步如果把「還沒踩過的格子」切成兩塊，這題當下就已經解不出來了
——你只能走進其中一塊，另一塊永遠到不了。但現在的 env 要等到 agent **自己四面被封死**才會終止，
中間那幾步策略完全不知道自己已經輸了。

**術語**：未訪子圖（扣掉 blocked、邊以非牆鄰接定義）的連通分量數 `c`。
`c ≥ 2` 是「不存在覆蓋全盤的一筆畫」的**充分條件**；
env 現有的死路終止（`action_masks()` 全 False）只覆蓋分裂**之後**、agent 真的無路可走的那一刻。

- held-out 失敗中死路佔比：6×6 **59.1%**（handover §6.5）、4×4 **100%**（本次實測，§6）。
- 學習面的效果：`c ≥ 2` 的狀態 value 會被學成 ~0 ⇒ 那個切開區域的動作 advantage 立刻變負。
  credit assignment 從「幾步之後才撞牆」縮短成「當下這一步」。

⚠ 它**不是**「無解」的充要條件。`c = 1` 仍可能無解（例如剩下的區域沒有 Hamiltonian path），
而 agent 自己走進死巷、未訪區卻仍連通的失敗**這個特徵抓不到**——那一類的量測見 §6。

## 3. 編碼決策：兩個純量，不是一個

| index | 名稱 | 值 |
|---|---|---|
| 8 | `unvisited_split` | `1.0 if c > 1 else 0.0` |
| 9 | `unvisited_components` | `min(c, 4) / 4` |

**為什麼不是只放分量數**：只放 `min(c,4)/4` 的話，「正常 = 0.25 vs 已死 = 0.5」的對比很小，
而這個值要跟 4,104 維的 conv 輸出一起進 `Linear(→256)`。如果結果是 null，
就會分不清是「機制不成立」還是「編碼太弱」——而這個實驗的用途正是當 GNN 那條路的證偽測試
（見 `2026-09-05_rl-budget-and-design-notes.md` §5.6），**不能讓編碼強度變成 confound**。
機制本身是二值的（切開＝已輸），所以直接把閾值後的 bit 餵進去，不要求網路自己去學那個門檻。

**為什麼上限是 4**：`c ≥ 2` 之後資訊已飽和（都一樣是輸），再區分 5 塊或 9 塊沒有意義。
`c = 0`（全部走完）自然落在 0.0。**這個 4 沒有實驗依據**，但也不需要——它不改變任何判讀。

**成本**：每次 `_get_obs()` 一次 flood fill，O(格數)。§3.14 已用 A/B 量過同等成本 = **+4.6% 訓練時間**。

## 4. 為什麼做成開關（預設 off）

打開會讓 `scalars` 從 `(8,)` 變 `(10,)`，而 policy 第一層是 `Linear(4104→256)`
⇒ **維度一變，既有 checkpoint 就再也 `--resume` 不動了**，包括 6×6 那顆 8M 步的 `goal2_6x6_bigdata`。
所以 `Goal.connectivity_features` 預設 `False`，CLI 用 `--connectivity-features / --no-connectivity-features`
（`argparse.BooleanOptionalAction`，預設 `None`，`resolve_goal()` 以 **`is not None`** 判斷）。

⚠ 這是 `--shaping-lambda` 那個坑的同型：**`False` 和 `0.0` 一樣是假值**，
用 `store_true` 或真值判斷會讓「明確關掉」無法表達、對照靜默失效。
`test_connectivity_features_override_carries_both_directions` 在守這件事。

**副作用是好的**：兩臂的差別剛好就是這一個 flag，而對照臂的觀測**逐位元不變**
（`test_connectivity_features_are_appended_without_touching_the_base_scalars`）。

## 5. 實驗設計與事前登記的判讀規則

3 seed × 2 臂、4×4、1M 步、資料集 `seed20300000_n20000_4-6`、held-out test（n=1,928，`deterministic=True`）。
seed 沿用 λ 實驗那組：`20260815 / 31415926 / 27182818`。**兩臂唯一的差別是這個 flag。**

**對照臂重跑而不引用舊數字**：舊的三個（0.8771／0.8392／0.8449）是改動前的程式碼跑的。
重跑多花 12 分鐘，換到「兩臂出自同一份程式碼」，外加一個免費的可重現性檢查——
**對照臂若回不到那三個數字，就是我的改動洩漏到了 off 臂**（比讀 diff 可靠，陷阱 #18）。

**判讀規則（事前定死）**：

- 主指標 = 兩臂 3 seed 的**平均差**，**> ±0.04** 才算有效；小於就報 null，不挑最好的 seed 講。
- 同時看**逐 seed 配對差**（會不會變號）與**臂內全距**——λ 那次就是靠這兩項確定是 null。
- **死路率**是機制指標：solve 沒動但死路率明顯降，代表特徵有進到策略、瓶頸在別處。
- greedy baseline 跨 6 個 run 應維持 0.115–0.117，那是評估端沒漂移的哨兵。
- 有效才上 6×6。**本次不跑 6×6**（而且它的 seed 雜訊還沒量，不能先下 0.0x 結論）。

## 6. 事前量到的訊號 headroom（決定這個實驗值不值得跑）

用**對照組模型**（`goal1_4x4_bigdata`，deterministic）跑 4×4 test 前 500 題，
每步另外算一次分量數，量「split 是否在終止前就亮燈、提前幾步」
（探針：`../hi-collab/scratch/probe_split_headroom.py`，`hi-collab/` 不進版控）：

```
solved            442/500 = 0.884
dead ends         58 (100.0% of failures)
split fired first 36 (62.1% of failures)
warning lead      median 2.0 steps, mean 2.83, max 10, zero-lead 1/36
split on a solved episode 0 (must be 0)
```

三件事：

1. **訊號真的有提前**：62.1% 的失敗在終止前就亮燈，中位數提前 2 步，只有 1/36 是零提前。
2. **從不誤報**：442 個成功局裡**一次都沒亮**（與「贏的路徑上未訪區永遠是路徑的尾巴」一致，
   `test_a_winning_path_never_reports_a_split` 把這件事釘成測試）。
3. **天花板可以算**：有預警的失敗佔全體 7.2 pp ⇒ 全部轉化掉是 0.884 → **0.956（+0.072）**。
   ⇒ **要跨過 ±0.04 門檻，策略得把這些預警轉化掉超過 55%。**

⚠ 這個天花板量在**對照組策略的失敗**上。帶著特徵重訓的策略探索路徑會不同，
所以它是量級估計，**不是嚴格上界**。另外剩下 **37.9% 的失敗完全沒有預警**
（未訪區仍連通、但 agent 自己走進死巷）——那一類要靠割點／度數約束才抓得到，
**本次刻意不做**（一次只改一件事），但它是下一個有機制的候選，而且 headroom 已經量出來了。

## 7. 結果

### 7.1 表

4×4、1M 步、held-out test（n=1,928，`deterministic=True`）。

| 臂 | s20260815 | s31415926 | s27182818 | 平均 | 臂內全距 | 死路率 | 訓練秒數 |
|---|---|---|---|---|---|---|---|
| off（對照） | 0.8771 | 0.8392 | 0.8449 | **0.8537** | 0.0379 | 0.1463 | 244.7 |
| on（連通性） | 0.8242 | 0.8247 | 0.8335 | **0.8275** | 0.0093 | **0.1725** | 261.7 |

```
between-arm difference of means : -0.0263
largest within-arm spread       :  0.0379
paired per-seed differences     : -0.0529, -0.0145, -0.0114   <- 三個同號
greedy baseline across 6 runs   :  0.1146-0.1170 (spread 0.0024)
```

**兩個哨兵都乾淨**：

- **對照臂逐位元重現舊數字**（0.877075／0.839212／0.844917，三個 seed 差 +0.000000，連子指標都相同）
  ⇒ 改動沒有洩漏到 off 臂。
- **同 seed 的 greedy 與 masked_random 在兩臂逐位元相同**（0.117038／0.116572／0.114601）
  ⇒ 這個特徵**確實只動觀測、沒動 env 動態**，評估端也沒漂移。

### 7.2 判讀：未達門檻 ⇒ **null**，但方向一致為負

差的絕對值 **0.0263 < 0.04** ⇒ 照 §5 事前登記的規則，**這個改動無效，不進 6×6**。

⚠ 但它**不是 λ 那種乾淨的 null**：λ 的逐 seed 配對差會變號（+0.038／+0.006／−0.018），
這次**三個 seed 全部是負的**，而且**死路率三個 seed 全部上升**、覆蓋率三個 seed 全部下降。
三個同號在虛無假設下的機率是 1/8，不足以宣稱顯著，
但**誠實的寫法是「沒有證據支持它有幫助，而點估計是負的」**，不是「沒有差別」。

### 7.3 機制診斷：策略**沒有在用**這個訊號

同一個探針、同樣的 500 題，換成實驗臂的模型（`probe_split_headroom.py`）：

| | 對照臂 | 實驗臂 |
|---|---|---|
| solve | 0.884 | 0.808 |
| 失敗中「終止前就亮燈」 | 62.1% | **64.6%** |
| 亮燈失敗佔全體題目 | 7.2% | **12.4%** |
| 提前步數中位數 | 2.0 | 2.0 |
| 成功局誤報 | 0 | 0 |

**看得到訊號的策略，反而更常走進分裂**，而「亮燈失敗佔失敗的比例」幾乎不變（62.1% → 64.6%）
⇒ **這個 null 不是「編碼太弱所以量不到」，是「把答案放進觀測，並不會讓策略避開那一步」。**
（絕對次數變多主要是因為它整體就是比較差的策略；**占比不變**才是那個 scale-free 的證據。）

**為什麼**（這是解釋，不是實測結論）：訊號在**時序上晚一步**。
策略選動作時看到的是**當前**狀態，而當前狀態還沒分裂；分裂只出現在**下一個**觀測裡。
要避開它，策略仍然得學會「這一步會造成分裂」——**跟沒有這個特徵時要做的一步前瞻是同一件事**。
這個特徵能讓 value function 更容易把「已經輸了」的狀態標成 0，
但**沒有在決策當下給策略任何可行動的資訊**。

⇒ **有機制、便宜、可測的下一個版本是「動作條件版」**：對四個方向各算一次「這一步會不會造成分裂」
（4 個純量，同一次 BFS 預算內做得完），那個訊號在**做決定之前**就存在。
本次刻意不做（一次只改一件事），但它是這條線唯一還沒被推翻的方向。

### 7.4 一個未排除的替代解釋：curriculum 被拖慢了

推到全長（k=15 → 全長）所需步數，**三個 seed 全部是實驗臂比較慢**：

| seed | off | on | 差 |
|---|---|---|---|
| 20260815 | 361,520 | 397,296 | +35,776 |
| 31415926 | 358,512 | 420,256 | +61,744 |
| 27182818 | 300,832 | 348,304 | +47,472 |
| 平均 | 340,288 | **388,619** | **+48,331（+14.2%）** |

⇒ 實驗臂**在全長上少練了約 7.4%**（660k vs 611k 步）。
**所以「特徵讓最終策略變差」與「特徵拖慢 curriculum，導致全長訓練不足」目前分不開**——
兩者都是這個改動造成的，但機制不同。
**最便宜的判別方式**：給實驗臂補上等量的全長步數（約 +50k 步／run，三個 seed 共約 4 分鐘）再比。
本次沒做。

### 7.5 對 GNN 那條路的意義

報告 `2026-09-05_rl-budget-and-design-notes.md` §5.6 的論證是
「把拓撲答案直接當 scalar 餵進去若無效，GNN 幾乎不可能有效」。
**這次的結果支持那個論證，但要換一個更精確的說法**：

失敗的原因**不是**「網路算不出連通性」（我們直接把答案餵進去了，而且它從不誤報），
而是**「當前狀態的連通性，本來就不是該拿來條件化的量」**。
**GNN 算的也是當前狀態的圖性質，所以它繼承同一個限制。**
⇒ **GNN 仍然不該現在做**；要動這條線，先做 §7.3 的動作條件版——它便宜兩個數量級，
而且是同一個假設更公平的版本。

⚠ 這仍然**測不到 GNN 唯一真正的優勢**：跨盤面尺寸的泛化。那件事這個實驗沒有發言權。

### 7.6 事故記錄：評估路徑漏接（花掉三個實驗臂的評估）

**現象**：三個實驗臂**訓練 100% 正常跑完**（1M 步、curriculum 推到全長、checkpoint 全存），
但**評估階段崩潰**，沒有產出 `eval_test.json`。traceback 停在 SB3 深處
（`policies.py:258 obs_to_tensor` → `utils.py:489 is_vectorized_observation`）。

**根因**：`baselines.evaluate()` 自己建 env，而它不知道有 `connectivity_features`
⇒ 訓練 env 給 10 個純量、評估 env 給 8 個。我把 flag 從 CLI 接到 `make_vec_env()`，
**還特地驗過「CLI → goal → 訓練 env」三段**，但那個驗證涵蓋不了評估那條路。

**代價與處理**：訓練一步都沒浪費（`model_final.zip` 在 `score()` **之前**就存好），
只需要重跑評分（`rescore_conn_runs.py`，從 checkpoint 重放同一個 `score()`）。

**防線**（已落地）：

1. 評估的 env 建構收斂成唯一的 `baselines.make_eval_env()`。
2. `test_training_and_evaluation_envs_agree_on_the_observation_space`（兩臂各一，parametrized）
   ——釘住的是**不變量**「訓練 env 與評估 env 的觀測空間必須相同」，而不是再多驗一條路徑。
3. 修補後**用效果驗證**：對照臂在修補後的程式下重新評分，結果與 loop 產生的 `eval_test.json`
   **完全相同**，證明 off 臂沒有被這次修補改到。

**一般化的教訓**（已寫進 handover 陷阱 #24）：**env 有兩個建構點**，
設定接到「當下想到的那一個」不算接好；而**驗了熱路徑的一部分不等於驗完**。

### 7.7 成本實測

實驗臂訓練 261.7s vs 對照臂 244.7s ⇒ **+7.0%**，略高於 §3.14 先前 A/B 量到的 +4.6%。
⚠ 對照臂自己的三次就差 12.9s（5.3%），所以這兩個數字**沒有真的矛盾**，量級一致。

## 8. 本報告未驗證的部分

- **「特徵讓策略變差」與「特徵拖慢 curriculum 導致全長練不夠」沒有分開**（§7.4），
  判別方式已寫明但沒做。
- **動作條件版（這一步會不會造成分裂）沒做**（§7.3），那是這條線唯一還沒被推翻的方向。
- 只測 4×4。6×6 沒跑，其 seed 雜訊也仍未量。
- 沒有測 `min(c,4)` 上限、沒有測「只放一個 scalar」的編碼——刻意不開這些變數。
- 割點（articulation points）沒做。
- 這個測試**測不到 GNN 唯一真正的優勢**：跨盤面尺寸的泛化（現在 `Linear(4104→256)` 綁死 8×8 padding）。
  所以無論有效無效，都不能拿來把 GNN 整條路結案。
