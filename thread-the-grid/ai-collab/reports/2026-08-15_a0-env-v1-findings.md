## 2. 發現 1（新，最致命）：合法一筆畫解永遠無法終止

### 白話版

env 在開局時把 agent 放在「數字 1」的格子上，但它心裡的「下一個要收集的目標」**也是數字 1 那一格**。
問題是它只在「移動之後」才檢查有沒有踩到目標——而 agent 一開始就站在上面，不算數。
於是要拿到第 1 個號碼，agent 必須**先走開、再踩回來**。
可是合法的 Zip 解答一格只能走一次，永遠不會回頭，所以號碼 1 永遠收集不到，
後面的號碼也就跟著卡住，「全部收集完＋走遍全格」的過關條件**在數學上不可達**。

### 術語版

`rl_env.py:45-47` 取 `waypoints[0] = num_map[1]` 並令 `start_pos = waypoints[0]`；
`reset()`（`:143-146`）設 `_agent_location = start_pos` 且 `_next_waypoint_idx = 0`，
因此 t=0 時 `target_pos == _agent_location`，但 `reset()` 不做收集判定。
`step()` 的收集判定（`:199-208`）在移動後才執行，於是 `_next_waypoint_idx` 只可能被
**重新進入起點**的那一步推進。Hamiltonian path 不重複造訪 ⇒ 索引恆為 0 ⇒
`is_final_waypoint`（`:200`）恆假 ⇒ `terminated`（`:203-205`）不可達。

### 證據（probe 1，`terminated` 全為 False）

| 題目 | 盤面 | waypoints 收集 | 走過格數 | 合法解總報酬 |
|------|------|----------------|----------|--------------|
| puzzle_01 | 6×6 有牆 | 0 / 8 | 36 / 36 | −35.03 |
| puzzle_02 | 6×6 無牆 | 0 / 12 | 36 / 36 | −35.05 |
| puzzle_03 | 6×6 有牆 | 0 / 12 | 36 / 36 | −35.03 |
| puzzle_04 | 7×7 有牆 | 0 / 12 | 49 / 49 | −48.06 |
| puzzle_05 | 6×6 有牆 | 0 / 12 | 36 / 36 | −35.09 |
| puzzle_06 | 7×7 無牆 | 0 / 21 | 49 / 49 | −48.02 |
| 出題器生成 4×4（seed 42） | 4×4 無牆 | 0 / 5 | 16 / 16 | −15.03 |

走過格數欄位證明重播本身是對的（每一格都走到了），失敗的是 env 的收集判定。

**probe 2 直接拍到機制**：`reset` 後目標＝起點（`start_is_first_target: true`）；
往外走一步 → 索引仍是 0；**踩回起點 → 索引 0→1，並吐出 +197.01**。

## 3. 發現 2：成功終局只對「違規重踩起點」的路徑開放

把同一條 ground truth 前面接上 `起點 → 鄰格 → 起點` 的繞路（**這不是合法 Zip 解**，起點被踩兩次），
6 題 conftest 題目**全部 terminated=True，末步報酬 +999.01**：

| 題目 | 合法解（一筆畫） | 非法繞路解 |
|------|------------------|------------|
| puzzle_01 | 未終止，總報酬 −35.03 | ✅ 終止，總報酬 **+2359.15** |
| puzzle_02 | 未終止，−35.05 | ✅ 終止，**+3159.33** |
| puzzle_03 | 未終止，−35.03 | ✅ 終止，**+3159.29** |
| puzzle_04 | 未終止，−48.06 | ✅ 終止，**+3146.26** |
| puzzle_05 | 未終止，−35.09 | ✅ 終止，**+3159.17** |
| puzzle_06 | 未終止，−48.02 | ✅ 終止，**+4946.40** |

`all_cells_visited` 用的是 `len(set(path_taken)) >= total_visitable_cells`（`:201`），**允許重走**，
所以繞路不但沒被擋，還因為多收集一次 waypoint 而多賺 +200。

**這條的意義**：2025-10 那次訓練，agent 能拿到的最高分策略在定義上就是**違規**的。
就算當時 DQN 學得很好，學到的也會是「先繞回起點再開始走」——而那不是 Zip 的解。
換句話說，**當年的失敗有一部分不是 RL 的問題，是環境把題目寫錯了**。

> 這一點修正了 restart plan 報告 §2.4 的說法。原文說「隨機探索撞出完整 Hamiltonian path 的機率趨近於零 →
> 整個訓練過程幾乎沒有正樣本」。實測更精確的說法是：**撞出合法 Hamiltonian path 的正樣本機率不是趨近於零，是恰好為零**；
> 有正樣本的那條路徑類別（重踩起點）本身就違規。§2.4 的結論（稀疏終局害死探索）方向仍然對，程度被低估了。

## 4. 發現 3：2-cycle 假說成立（設計前提保住）

報告 §2.1 的推論已用實驗復現，**不需要重審整份設計**。

- **probe 3**：在兩個已訪格 `(4,5) ↔ (3,5)` 間來回 8 步 → 觀測雜湊只有 **2 個相異值**
  （`a7091111`／`301def9c`），嚴格交替，報酬也只在 −2.99／−3.01 間交替。
- **probe 4**（更強的版本）：用那兩個觀測建一個只有 2 個狀態的**確定性**策略 π，讓它接手跑 →
  **69 步直到 truncated，`escaped=False`，全程只碰過 2 個格子**。
  這就是「訓練期分數漂亮、`deterministic=True` 評估必掛」的完整機制，不再是推測。

## 5. 發現 4：非法移動不計入預算，撞牆可以撞到天荒地老

`step()` 的非法移動分支（`:176-180`）直接 `return observation, -10.0, False, False, info`，
**`truncated` 寫死 False**。probe 5：從 `(2,5)` 對著邊界撞 **82 次**（步數預算只有 72）→
觀測**只有 1 個相異值**、agent 沒動、**truncation 從頭到尾沒被回報過**。

後果：一個「只會撞牆」的策略會產生**永不結束的 episode**。這在 SB3 的 `n_steps` rollout 下不會把行程掛住，
但整段 rollout 會被浪費掉。v2 的 action masking 從設計上就消掉這個分支，屬於已被解決的問題，這裡只是留檔。

## 6. 發現 5（附帶，給 A1 用）：出題器在奇數盤有 parity 失敗率

A0 寫測試時撞到：`generate_puzzle(m=5, n=5)` 在 seed `20260815` 下 5 次 retry 全滅。查證後確認是 parity：

- 5×5 對 25 格做黑白染色，`(r+c)` 偶數有 13 格、奇數 12 格；Hamiltonian path 必須交替顏色，
  故**只能從多數色出發**。實測固定每個起點各跑一次：**偶數格 13/13 成功、奇數格 0/12 全滅**。
- `_generate_hamiltonian_path` 每次 attempt 都 `random.choice` 重挑起點（`puzzle_generator.py:158`），
  挑中少數色的機率 12/25，連挑 5 次都中的機率 ≈ 2.5%。實測 40 個 seed **失敗 1 個（seed 35）**，與預測相符。

**對 A1 的影響**：離線生成題庫時，奇數盤（5×5、7×7）會有一定比例的題目直接回 `None`，
而且每次失敗要吃掉 5 次 retry 的搜尋時間。**A1 的資料生成迴圈必須處理 `None` 並換 seed 重試**，不能假設一定拿得到題目。
根治的做法（在奇數盤只從多數色挑起點）要動 `src/core/puzzle_generation/`，
依計畫書 §7 那是「只讀不改」的共用模組，**所以我不動它，只提報**；要不要修由本人決定。

### ✅ 2026-08-15 補測：不改共用模組也能省 18 倍

那 20 秒不是花在「找解答」，是花在**證明一個 parity 不對的起點無解**。實測 7×7（單執行緒、40 個 seed）：

| 每次嘗試的 timeout | 成功率／次 | 成功者的耗時 |
|---|---|---|
| 0.5s | 7/40 | 最慢 **0.415s** |
| 2.0s | 9/40 | 最慢 1.606s |

**會成功的搜尋幾乎都在 0.4 秒內結束**，等滿 20 秒純粹是在等注定失敗的搜尋。
`timeout_per_attempt` 是 `generate_puzzle()` 的呼叫端參數，**不必動共用模組**：改成 0.5s 之後，
5,100 題（4/5/6 各 1700）從外推的約 23 小時降到 **45 秒**；7×7 也只要 **35 秒／100 題**（98/100 成功）。
`generate_dataset_v2.py` 已將它預設為 0.5s 並可用 `--timeout` 覆寫。

## 7. 對 A1 的具體影響（env v2 要帶走的條款）

1. **v2 的 `reset()` 必須在開局就收下起點的 waypoint**（或改成「站上去即收集」的判定），
   並且**第一件事就是重播 ground truth 的驗收測試**——A1 的 done 條件要包含「合法解重播必 terminated」。
   這正是計畫書 A0 設計的價值：這個測試若當年存在，第一天就會擋下整條錯路。
2. **終局判定要真正檢查一筆畫**：`len(set(path)) >= visitable` 在允許重走的 Phase 1/2 是刻意的，
   但**評估時的「合法一筆畫率」必須另外用 `len(path) == len(set(path))` 判定**（計畫書 §6 已要求分開報，這裡補上實作理由）。
3. **非法動作在 v2 靠 mask 消除**；若仍保留 fallback 分支，`truncated` 必須照常計算，不能寫死 False。
4. **資料生成要容忍 `None`**（發現 5）。
5. 2-cycle 的解法（visit count ＋ 嚴格單調的 `time_used`）維持原案，**實驗支持，不需改動**。
