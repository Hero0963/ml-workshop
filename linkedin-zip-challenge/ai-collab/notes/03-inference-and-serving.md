# 訓練好的模型實際怎麼解一題

> 2026-09-11 被問「實務上要怎麼推理？input = 目前盤面，output = 下一個點，這樣嗎」。
> 答案是「方向對，但輸出是方向不是座標」。這份把整條推論路徑寫清楚，也是 A5（掛成 API）的依據。
> Last Updated: 2026-09-11

---

## 1. 單步：輸入什麼、輸出什麼

```python
obs  = env.observation()      # {"grid": (8, 8, 8) float32, "scalars": (8,) float32}
mask = env.action_masks()     # (4,) bool -- 撞牆／出界／已踩過 -> False
action, _ = model.predict(obs, deterministic=True, action_masks=mask)
                              # action in {0: Up, 1: Down, 2: Left, 3: Right}
env.step(action)              # 下一個點 = 目前位置 + 該方向
```

**輸出是四個方向的機率分布**，不是座標。遮罩把非法動作壓成 0，再取 argmax（deterministic）
或抽樣（best-of-N）。「下一個點」是**相對移動**推出來的。

**輸入的 8 個 grid channel**（每個都是 8×8，小盤面補零）：

| # | channel | 意義 |
|---|---|---|
| 0 | valid | 這格可以走嗎（扣掉 blocked）|
| 1 | wall_right | 這格右邊有牆 |
| 2 | wall_down | 這格下面有牆 |
| 3 | visited | 已經走過 |
| 4 | agent | 目前位置 |
| 5 | wp_next | 下一個要收的編號在哪 |
| 6 | wp_future | 更後面的編號在哪 |
| 7 | wp_done | 已經收過的編號 |

**8 個純量**：包含 `height/8`、`width/8`（所以模型知道盤面多大），其餘見 `rl_env_v2.py` 的 docstring。

---

## 2. 整題：把單步跑 `格數 − 1` 次

- 6×6 ＝ **35 次 forward**，一次約 1.2 毫秒 ⇒ **deterministic 解一題約 40 毫秒**
  （實測：2,000 題 80.9 秒）。
- **失敗的長相不是「輸出錯誤答案」，是「卡住」**——走到某格四個方向全被遮罩 ⇒ 死路，該次記 0 分。
- 正常結束是走完所有可走格且編號順序正確。

---

## 3. best-of-N：整題從頭重跑

因為 Zip 的解**可驗證**，所以「多試幾次、留成功的那次」是合法手段，不是猜：

```
for attempt in 1..N:
    走完整題（這次用抽樣而非 argmax）
    if 解開: break      # 第一次成功就停 -> 記錄到的嘗試次數就是部署成本
```

| 6×6（2,000 題 held-out）| deterministic | best-of-16 | best-of-32 | best-of-64 |
|---|---|---|---|---|
| solve | 0.4620 | 0.8105 | **0.8500** | 0.8835 |
| 平均嘗試／題 | 1 | 5.35 | 8.05 | 12.25 |
| **每題耗時**（約 47ms／次）| 40ms | 0.25s | **0.38s** | 0.58s |

⇒ **掛成 API 完全可接受**：6×6 best-of-32 平均每題約 0.4 秒。

4×4 便宜得多：**best-of-2 就過 0.90**（0.9248，平均 1.14 次／題）。

## 4. 要拿哪一個 checkpoint

| 盤面 | 模型 | deterministic | best-of-32 |
|---|---|---|---|
| 4×4 | `models/rl_a2/bc_4x4` | 0.8947 | ≥ 0.9533（best-of-4 就有）|
| 6×6 | `models/rl_a2/bc_6x6` | 0.4620 | 0.8500 |
| 5×5 | **沒有專屬模型**（2026-09-11 狀態）| 借 `bc_6x6` ＝ 0.2941 | 待多尺寸模型 |

- checkpoint 是 `MaskablePPO.load()` 吃的 `.zip`，BC 與 PPO **同架構、可互換**。
- `models/` **不進版控** ⇒ 部署時要掛 volume 或另外傳，不能假設 clone 下來就有。

---

## 5. 掛成服務時必須處理的四件事

1. **模型檔不存在** → 回 **503**（服務暫時不可用），不要變成 500 堆疊追蹤。
2. **盤面尺寸沒有對應模型** → 回 **400**，訊息要說清楚支援哪些尺寸。
3. **解不出來** → 這是**正常結果**不是錯誤：回 200 並說明「這個 solver 沒找到解」，
   既有的 `/api/solver/solve` 已經有這條路徑。
4. ⚠ **分布外**：RL 的訓練資料每題是 **0 或 2–5 道牆**，
   而 VLM 從真實截圖讀出來的可以到 **10 道以上** ⇒ 從 `/api/vision` 流過來的題目對 RL 是分布外，
   **要標示為實驗性**，不要默默給一個爛答案。

## 6. 和傳統 solver 的關係（別搞錯定位）

專案裡已經有 9 種傳統 solver，CP-SAT 又快又保證正確。
**RL solver 不是為了比它好**——它在 6×6 上 deterministic 只有 0.46，加了 32 倍預算才勉強到 0.85。

RL solver 的價值是**做中學**：學 masking、curriculum、模仿學習、推論期搜尋這一整套。
掛進 API 是為了讓這條 track 有個看得見的終點，**不是因為它是最好的解法**。
