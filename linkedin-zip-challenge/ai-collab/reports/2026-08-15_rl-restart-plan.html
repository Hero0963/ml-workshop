1. 結論先講

你的兩個直覺都對，而且它們正好互補。

①「允許倒車重試比較好訓練」——對。強制一筆畫會讓 agent 一走進死路就結束，訓練初期幾乎每一集都是失敗，等於沒有學習訊號。允許倒車讓它有機會「走錯再回頭」，把稀疏的成功事件變得可及。

②「visit 次數要進 observation」——對，而且這一條直接解掉 v1 診斷的 2-cycle。舊環境的 path 是二值的，走過就是走過，所以來回震盪時觀測不變、確定性策略卡死。改成造訪次數之後，每回頭一次觀測就變一次，迴圈不再是不動點。
但還缺一塊才嚴謹：visit count 若做上限截斷（例如 clip 到 4），飽和後又會退化成常數。所以要再加一個嚴格單調的量——已用步數／預算，那麼觀測序列在數學上就永遠不可能循環。

③「越快完成越好，像冰湖」——對，但實作方式建議用折扣因子 γ，而不是每步扣分。冰湖的 reward 就是「到終點 +1、其他 0」，速度是由 γ<1 自然壓出來的。舊版每步 −1 累積到 −72，把 +1000 的終局訊號稀釋掉了，這是尺度失衡。

整體設計＝三階段課程：Phase 1 寬鬆（隨便倒車）→ Phase 2 收緊（倒車開始要付代價）→ Phase 3 一筆畫（直接 mask 掉已走過的格）。你最理想的「一筆畫」是終點，不是起點。

2. 2025-10 那次失敗的機制性根因

當時 dev_log 的結論是「dense reward trap 造成 deterministic policy loop，調權重無效」。這描述對，但停在現象層。讀完 src/core/rl/rl_env.py 後可以給出機制層解釋：那個迴圈不是訓練不足，是環境設計讓它成為必然。

2.1 死因一：觀測空間裡存在 2-cycle（決定性的）

白話版

agent 只看得到「哪些格走過（走過就是走過，不分次數與先後）」「我在哪」「下一個目標在哪」。當它在兩個已走過的格子間來回跳，畫面其實沒變——走過的還是走過，目標還是那個。於是模型看到的世界只剩兩個畫面 A 和 B，而測試時是固定決策：「看到 A → 去 B」「看到 B → 去 A」，永遠出不來。訓練時有隨機探索才會意外跳出去，這正解釋了「訓練分數漂亮、評估必掛」。

術語版

觀測由 6 個 channel 組成（rl_env.py:104-128）：blocked、horizontal walls、vertical walls（三者靜態）、path_taken（二值集合）、agent 位置、下一個 waypoint 位置。設 agent 在已訪格 A、B 間震盪：ch_path 不變（二值化抹掉次數與順序）、ch_waypoint 不變（索引沒遞增），只有 ch_agent 交替。因此觀測序列為 o_A, o_B, o_A, o_B, …，確定性策略 π 是觀測的函數，該迴圈是策略的不動點，直到 truncated。dev_log 記錄的 (4,0) ↔ (5,0) 正是這個形狀。

還有退化版的單點迴圈：非法移動時 agent 不動、不入 path、也不 terminate，只吃 -10（:176-180）。「一直撞同一面牆」同樣是不動點——觀測完全不變，動作完全不變。

你的提案為什麼正好命中：把 path 從二值改成造訪次數，A↔B 每來回一次計數就 +1，觀測就變了 → 上圖那個閉環被打開。
但要補一刀才嚴謹：計數若 clip（實務上一定要 clip，否則數值無界），飽和後仍可能退化。所以觀測必須再帶一個嚴格單調的量（已用步數／預算）。有了它，任兩個時刻的觀測必不相同，循環在數學上被排除，而不是靠「大概不會」。

2.2 死因二：shaping 的位能與真正目標不同構

shaping 項是 (dist_before - dist_after) * weight（:193），等價於位能 Φ(s) = −曼哈頓距離(agent, 下一個 waypoint)。potential-based shaping（Ng, Harada & Russell, 1999）保證最優策略集合不變，但不保證學習動態不被扭曲，更不會讓一個「錯的目標」變成對的。真正的目標是「依序經過所有 waypoint 且走遍每一格」，位能卻只描述「靠近下一個號碼」。要填滿角落必然得暫時遠離下一個號碼，shaping 一路給負回饋 → 策略學會貼著號碼跑，而那恰恰解不了 Hamiltonian path。所以權重從 0.1 調到 0.01 沒用是必然的。

2.3 死因三：agent 看不到未來的 waypoint

_get_obs() 只放下一個 waypoint（:114-116）。走 1→2 時完全不知道 3、4、5 在哪 → 「規劃一條同時滿足順序與全覆蓋的路線」在資訊上不可能，只能貪心。這與 reward 無關，是資訊瓶頸。

2.4 死因四：稀疏終局 ＋ 天文數字的搜尋空間

7×7 要走完 49 格才拿得到 +1000（:199-205）。隨機探索撞出完整 Hamiltonian path 的機率趨近於零 → 整個訓練過程幾乎沒有正樣本。這是探索問題，調權重同樣無解。

3. 問題本質與 RL 的定位

白話版

Zip 不是走迷宮，是「一筆畫」：不重複踩過每一格，還要照號碼順序。這是電腦科學裡出名的難題，而你的專案已經有一個解得又快又正確的工具（CP-SAT）。所以 RL 的價值不是解得更好，而是學會方法，以及訓練一個對沒看過的新題目能一次前向就給答案的模型。

術語版

Zip ＝ 帶順序約束的 Hamiltonian path problem，NP-hard。專案現況：CP-SAT（src/core/solvers/cp.py）給精確最優解，DFS 給可行解，六種啟發式給近似解，全部有 ground-truth 測試。

RL 的定位（誠實版）：不是為了比 CP-SAT 快或準（不會贏）；是為了學 masking／PPO／curriculum／MCTS／RLVR；是為了得到攤提式（amortized）解題器——訓練一次，之後每題一次前向傳播（毫秒級）；也是為了讓 API 多一個能展示的 solver。

4. 路線 A：實驗全新設計

4.1 三條設計原則

  1. 觀測必須單調前進：任兩個時刻的觀測不得相同 → 迴圈在結構上不可能。用「visit 次數 ＋ 已用步數比例」達成。
  2. 約束用 masking 表達，偏好用 reward 表達。物理上不可能的事（出界／穿牆／踩到順序錯的號碼）一律 mask，不用扣分教；「希望它少繞路」才用 reward。舊版把兩者混在一起（非法移動扣 −10），是 −10 這個數字在跟 +1000 搶尺度。
  3. 速度用折扣因子表達，不用時間懲罰。見 4.4。

全部 padding 到 8×8，讓同一個模型吃 5×5～8×8 的題目。

4.3 動作空間與 masking 政策

動作維持 4 個（上下左右）。每一步都提供 action mask，遮掉：

  1. 出界
  2. 目標格是障礙（blocked_cells）
  3. 兩格之間有牆
  4. 目標格是「順序錯的 waypoint」——例如 3 還沒收，卻要踩 5。這是遊戲規則，屬物理非法，舊版沒有處理這條
  5. （僅 Phase 3）目標格已被造訪 → 強制一筆畫

效果：非法移動的 -10 懲罰整條消失，環境不再有「撞牆不動」的退化不動點；動作空間永遠只剩合法選項，策略學習的難度大幅下降。文獻與實務都指出，masking 比懲罰法／重取樣法更穩定、收斂更快（把非法動作的 logit 設 −∞ 再 softmax，梯度為 0）。

邊界情況要處理：Phase 3 下可能出現「四個方向全被 mask」（走進死路）。SB3 的 MaskablePPO 遇到全 False 的 mask 會出錯，所以環境必須在該狀態直接 terminated=True（失敗），不要讓它進到取樣階段。這是實作時最容易漏的一個 bug。

4.4 Reward 重新設計（冰湖式）

白話版：為什麼不要每走一步就扣分

每步 −1 聽起來很自然（「快點走完」），但有兩個副作用。第一，agent 沒有「認輸」按鈕，它逃不掉扣分，於是「早死早超生」不可行，反而學會擺爛。第二，尺度會打架：走 72 步就是 −72，而終局才 +1000／中繼 +200，訓練初期永遠拿不到終局獎勵，所以模型看到的世界幾乎全是負分，訊號被時間懲罰淹沒。冰湖遊戲的處理更漂亮：到終點 +1，其他一律 0，速度交給折扣因子。因為晚 10 步拿到的 +1 打了折（0.99¹⁰ ≈ 0.90），「越快越好」自動成立，一個權重都不用調。

術語版

最大化 γ^T · R_success 等價於最小化 T。時間懲罰是把速度寫進即時獎勵，會與稀疏終局獎勵爭奪尺度、放大 return 變異；折扣是把速度寫進目標函數本身，無額外超參。Gymnasium 的 FrozenLake 正是這個設計（抵達目標 +1，其餘 0）。

# === Reward 規格 v2 ===
gamma = 0.99                     # 「越快越好」由這裡表達

success        = +1.0            # 唯一的大獎：依序收完所有 waypoint 且走遍所有可走格
failure        =  0.0            # 步數用盡：不額外懲罰（避免誘發自毀行為）
dead_end       =  0.0            # 僅 Phase 3：無合法動作 -> terminated

# 覆蓋型 potential shaping（Phase 1-2 開，Phase 3 關）
Phi(s)  = 已訪不同格數 / 可走格數           # <- 與真正目標同構，不是距離
F(s,s') = lambda * (gamma * Phi(s') - Phi(s))
lambda  = 0.5

# 重走成本（三階段 anneal，見 4.6）
revisit_cost = c * (visit_count_before - 1)   # c: 0 -> 0.005 -> 改用 mask

與舊版的關鍵差異：位能從距離換成覆蓋率。這一步是整份設計的核心——距離位能會懲罰「為了填滿角落而暫時遠離下一個號碼」，覆蓋位能則獎勵它。位能與真實目標同構，shaping 才會幫忙而不是扯後腿。

4.5 終止條件與步數預算

事件條件回傳
成功所有可走格 visit_count ≥ 1 ∧ waypoint 依序全收 ∧ 位於最後一個 waypointterminated=True, +1.0
失敗（超時）已用步數 ≥ budgettruncated=True, 0
失敗（死路）Phase 3 且無合法動作terminated=True, 0

budget（步數預算）＝ k × 可走格數，k 隨階段收斂：Phase 1 k=3（大量倒車空間）→ Phase 2 k=2 → Phase 3 k=1（一筆畫的理論步數就是「格數 − 1」，沒有餘裕）。

一個必須講清楚的誠實點：Phase 1／2 允許重走，所以「成功」的路徑不一定是合法的 Zip 解（真實遊戲不能重複踩格）。這兩階段的成功是訓練用的軟目標，用來製造學習訊號。只有 Phase 3（或推論時強制 mask 已訪格）產出的才是合法一筆畫解。評估時要同時報「軟成功率」與「合法一筆畫率」，不能混為一談。

4.7 題目供給與網路架構

  • 每個 episode 隨機抽一題（不要再 overfit 單一地圖）。用 generate_rl_dataset.py 離線預生成 50k 題並固定 seed 切 train／val／test，避免生成器的內部逾時拖慢訓練迴圈（出題器有 timeout_per_attempt=20s，放在 rollout 迴圈裡會是災難）。

4.9 評估協定（含必備對照組）

先量兩個 baseline，否則無法證明模型學到東西：

  1. masked random：在合法動作裡均勻亂選。有了 masking 之後，這在 4×4 上的成功率可能意外地高——這正是必須先量的理由。
  2. greedy：永遠往下一個 waypoint 靠近（等於舊版 shaping 想教出來的東西）。它的成功率就是「距離型 shaping 的天花板」。
  • 主指標：1,000 題 held-out 的 deterministic 通關率，依尺寸分列，並同時報兩種推論模式——(a) 允許重走 (b) 推論時強制 mask 已訪格（＝直接要求一筆畫）。(b) 才是產品可用的數字。
  • 效率指標：平均步數 / 理論最少步數；revisit_ratio；合法一筆畫率。
  • 成本指標：單題決策延遲 vs DFS／CP-SAT 求解時間（RL 唯一可能贏的維度）。
  • 健全性測試（pytest）：把 ground-truth 解答路徑逐步餵進 env，斷言最後 terminated=True 且拿到 +1。這個測試若當年存在，第一天就能排除「環境本身不可解」。

6. 自己造輪子的可行度評估

結論：可行，規模約 900–1,200 行、2–3 週業餘時間；但建議「環境自己寫、演算法先用現成的」。

6.2 造輪子的取捨

  • 好處：零相依衝突（不用碰 torch pin）；學習價值最高——PPO 的 clip、GAE、mask 的梯度處理都會親手寫過一遍；而且你已經有 ../more_simple_reinforcement_learning/chap_05_ppo 可以對照。
  • 壞處：debug 成本高。RL 的 bug 不會報錯，只會「學不起來」，你會分不清是演算法寫錯、環境寫錯、還是超參不好。這正是舊實驗吃過的苦。

建議的折衷：先用 sb3-contrib 的 MaskablePPO 把整條路跑通、拿到成功率數字（此時你有了「已知能成功」的參考點），再選擇性地自寫一版 PPO 對拍——兩邊在同一環境同一 seed 下的學習曲線應該相近。有參考點的造輪子才學得到東西；沒有參考點的造輪子只會卡在「到底哪裡錯」。

7. 路線 B：GRPO 讓語言模型通關

白話版

另一種「讓模型通關」是：不另外訓小 agent，而是教語言模型自己寫出答案。讓它一次生成好幾個答案，用你寫好的解題程式當裁判打分，分高的做法被強化。因為你手上有能自動判對錯的裁判，這件事才做得起來。

術語版

GRPO／GSPO 屬於 RLVR（RL with Verifiable Rewards）：同題取樣一組回答，用可驗證 reward 算組內相對優勢，不需要 value network 或人工偏好標註。本專案的 verifier 現成：prepare_solver_input()、calculate_fitness_score() 與各 solver 的合法性檢查，全部有 46 個測試背書。

兩個關鍵決定：
① 先做純文字輸入（把題目用 layout 陣列＋walls 清單餵進去），不要一開始就吃圖片——否則答錯時分不清是「看錯圖」還是「不會解題」。
② 從 4×4 起步（16 步），7×7（49 步）一開始必然全 0 reward。

# Reward 階梯（大量部分分數，避免訓練初期全 0）
format_ok          +0.1   # 能解析出座標序列
all_in_bounds      +0.1
adjacency_ok       +0.2 x (合法相鄰步數 / 總步數)
no_wall_crossing   +0.2 x (未穿牆步數 / 總步數)
no_revisit         +0.1 x (不重複比例)
waypoint_order_ok  +0.2 x (依序命中比例)
full_coverage      +1.0
solved             +2.0   # 等價於既有 solver 驗證通過

基礎建設（與 VLM 報告共用）：Unsloth 支援 Qwen3-VL／Gemma 3／Gemma 4／Qwen2.5-VL 的 GRPO/GSPO；Qwen3-VL-8B 可在免費 Colab T4 跑 GSPO；Qwen3.5-4B 有官方 GRPO notebook；Gemma 4 有 E2B 的 Sudoku RL/GRPO notebook——Sudoku 與 Zip 同屬「網格＋硬約束＋可程式驗證」，reward function 的結構幾乎可以照抄。GSPO 只要設 importance_sampling_level="sequence"，對長輸出（我們的路徑就是長輸出）較穩定。限制：走 vLLM 快速推論時視覺層 LoRA 不支援（finetune_vision_layers=False），所以視覺能力要在 VLM 報告的 SFT 階段先練好。

誠實的期望值：路線 B 成功機率明顯低於 A，成本高一個數量級。文獻顯示 LLM 在網格謎題上系統性偏弱；Sudoku 的 GRPO 有成功案例，但都伴隨精心設計的 reward 與大量取樣。done 條件建議訂成「4×4 上把通關率從 baseline 顯著拉高」，不是「解出 7×7」。
